# Reinforcement Learning — Landscape and Taxonomy

## The Big Picture

Reinforcement learning is the study of agents that learn to act by interacting
with an environment, optimizing a scalar reward over time. Unlike supervised
learning, there is no labeled "correct action" — only a delayed, evaluative
signal. The whole field is downstream of one diagram and one equation.

```
+------------------------------------------------------------------+
|                  THE AGENT-ENVIRONMENT LOOP                      |
|                                                                  |
|        .-----------------.                                       |
|        |      AGENT       |   action a_t                         |
|        |  policy pi(a|s)  |--------------------.                 |
|        '-----------------'                     |                 |
|              ^                                 v                 |
|              |                       .-----------------.         |
|              |  state s_{t+1}        |   ENVIRONMENT    |        |
|              |  reward r_{t+1}       |  dynamics p,r    |        |
|              '-----------------------|                 |         |
|                                      '-----------------'         |
|                                                                  |
|   Goal: choose pi to maximize  E[ sum_t gamma^t r_{t+1} ]        |
+------------------------------------------------------------------+
                                 |
                                 v
+------------------------------------------------------------------+
|                   THE FORMALISM: A MARKOV DECISION PROCESS       |
|   (S, A, p(s',r | s,a), gamma)                                   |
|   Bellman expectation + Bellman optimality equations             |
|   See: 01-MDP-FOUNDATIONS.md                                     |
+------------------------------------------------------------------+
                                 |
                                 v
+------------------------------------------------------------------+
|        HOW DO WE SOLVE IT? (three regimes of knowledge)          |
|                                                                  |
|   MODEL KNOWN          MODEL UNKNOWN          MODEL UNKNOWN      |
|   (planning)           (learn values)         (learn policy)     |
|   ----------           --------------          --------------    |
|   Dynamic              MC / TD / Q-learning    Policy gradient   |
|   programming          SARSA / DQN             REINFORCE / PPO   |
|   (ch 02)              (ch 03-05)              (ch 06-07)        |
+------------------------------------------------------------------+
```

**Read top-down**: the loop defines the problem, the MDP formalizes it, and the
three regimes (do we have a model? do we learn values or the policy directly?)
organize every algorithm in the field.

## Old World → New World: What RL Is Not

You already know adjacent formalisms. RL is best located by contrast.

| You know...                       | RL differs by...                                          |
|-----------------------------------|-----------------------------------------------------------|
| Supervised learning (i.i.d. data) | Data is non-stationary and *generated by your own policy* |
| Optimal control (LQR, MPC)        | Dynamics/cost are unknown; you learn from samples         |
| Dynamic programming (OR ch 09)    | State/transition model often unavailable; bootstrap from data |
| Bandits                           | Actions have *delayed, state-changing* consequences       |
| Search (A*, minimax)              | The environment is stochastic and the model may be learned |

The single distinguishing feature is the **closed feedback loop**: your policy
determines the distribution of data you train on. This is what makes RL unstable,
sample-hungry, and theoretically delicate — and is why so much of the field is
about controlling that instability.

```
  SUPERVISED LEARNING            REINFORCEMENT LEARNING
  -------------------            ----------------------
  Fixed dataset D                Data depends on pi
  Minimize loss on D             Maximize return under pi
  i.i.d. samples                 Correlated trajectories
  One-shot prediction            Sequential, credit assignment
  Stationary target              Moving target (bootstrapping)
```

## The Core Vocabulary

These terms recur in every chapter. Fix them now.

```
+------------------------------------------------------------------+
|  TERM            MEANING                                         |
|  ----            -------                                         |
|  state s        the agent's situation; Markov => sufficient stat |
|  action a        what the agent chooses                          |
|  reward r        scalar signal; the ONLY objective               |
|  policy pi(a|s)  the agent's behavior (stochastic map s -> a)    |
|  return G_t      discounted sum of future rewards                |
|  value v_pi(s)   expected return from s under pi                 |
|  action-value    q_pi(s,a): expected return from (s,a) under pi  |
|  model p,r       environment dynamics (may be known or learned)  |
|  gamma           discount factor in [0,1)                        |
+------------------------------------------------------------------+
```

The reward hypothesis (Sutton): *every goal can be framed as the maximization of
expected cumulative scalar reward.* This is a strong, contestable claim — chapter
09 returns to where it strains (reward hacking, multi-objective problems).

## The Taxonomy: How Algorithms Divide

Four orthogonal axes carve up the entire algorithm space. Learning to read an RL
paper is largely learning to place it on these axes.

```
+------------------------------------------------------------------+
|                    AXIS 1: MODEL                                 |
|   MODEL-FREE                       MODEL-BASED                   |
|   learn v/q/pi from samples        learn or use p(s'|s,a)        |
|   Q-learning, PPO, SAC             Dyna, MCTS, MuZero            |
|                                    (ch 08)                       |
+------------------------------------------------------------------+
|                    AXIS 2: WHAT IS LEARNED                       |
|   VALUE-BASED         POLICY-BASED          ACTOR-CRITIC         |
|   learn q, act greedy learn pi directly     learn both          |
|   DQN, SARSA          REINFORCE             A2C, PPO, SAC        |
+------------------------------------------------------------------+
|                    AXIS 3: ON / OFF POLICY                       |
|   ON-POLICY                        OFF-POLICY                    |
|   learn about pi you follow        learn about pi' != behavior   |
|   SARSA, PPO, A3C                  Q-learning, DQN, DDPG, SAC    |
+------------------------------------------------------------------+
|                    AXIS 4: BOOTSTRAP (sample vs estimate)        |
|   MONTE-CARLO                      TEMPORAL-DIFFERENCE           |
|   full return, no bootstrap        bootstrap from own estimate   |
|   high variance, unbiased          low variance, biased         |
+------------------------------------------------------------------+
```

Axis 4 is the one engineers underrate. *Bootstrapping* — updating an estimate
toward another estimate — is the source of both TD's efficiency and RL's
instability. When bootstrapping combines with function approximation and
off-policy data, you get the **deadly triad** (ch 05), the central failure mode
of deep RL.

## One Problem, Every Method: A Unifying Thread

To see how the chapters connect, follow a single task — balancing a pole on a cart
— as the knowledge available to the agent shrinks.

```
+------------------------------------------------------------------+
|  WHAT YOU KNOW                  ->  WHICH METHOD                 |
|  -------------                      ------------                 |
|  full model (p, r), small S         dynamic programming  (ch 02) |
|  no model, can act, discrete A      Q-learning / SARSA   (ch 04) |
|  no model, large/continuous S       DQN / func approx    (ch 05) |
|  continuous actions                 policy gradient      (ch 06) |
|  want robust deep training          PPO / SAC            (ch 07) |
|  can simulate, want to plan         MCTS / world model   (ch 08) |
|  only a fixed log of episodes       offline RL           (ch 09) |
+------------------------------------------------------------------+
```

Every one of these is the *same* GPI loop — evaluate a policy, improve it — under
different constraints on what you can compute and observe:

```
   evaluate:  how do I estimate value?      improve: how do I get a better policy?
   --------------------------------------    ----------------------------------------
   DP:        full Bellman backup (model)    greedy argmax over the model
   MC/TD:     sampled / bootstrapped value   epsilon-greedy on learned q
   func appr: regression to TD targets       greedy / soft on q(s,a;w)
   pol-grad:  critic estimates advantage     gradient ascent on log pi * A
   model-based: plan with the model (MCTS)   search IS the improvement operator
```

Recognizing GPI under the surface is the single most useful lens for reading any
RL paper: identify *what plays the role of evaluation* and *what plays the role of
improvement*, and the algorithm's structure falls out immediately.

## The Three Recurring Trade-Offs

Three tensions appear in every chapter. Naming them now makes later material click
into place.

```
+------------------------------------------------------------------+
|  1. EXPLORATION  vs  EXPLOITATION   (ch 04)                      |
|     try new actions to learn   vs   take the best known action   |
|                                                                  |
|  2. BIAS  vs  VARIANCE           (ch 03, 06)                     |
|     bootstrap (biased, stable)  vs full return (unbiased, noisy) |
|     -- the TD<->MC dial; reappears as GAE's lambda               |
|                                                                  |
|  3. SAMPLE EFFICIENCY  vs  STABILITY   (ch 05, 07)               |
|     off-policy + model (efficient, fragile -- deadly triad)      |
|     vs on-policy (stable, sample-hungry -- PPO)                  |
+------------------------------------------------------------------+
```

Almost every algorithmic choice in RL is a stance on one of these three axes. PPO
favors stability over efficiency; SAC and DQN buy efficiency and pay for it with
the machinery (target nets, twin critics, KL anchors) needed to stay stable.

## Common Confusion Points

### "Isn't this just dynamic programming?"

DP (ch 02) assumes you *have* the model `p(s',r|s,a)` and can sweep the whole
state space. RL's hard case is model-free: you only get sampled transitions, and
the state space is too large to enumerate. RL = DP's recursion (the Bellman
equation) executed with *samples* and *approximation* instead of full sweeps.

### "Reward vs return vs value — which is the objective?"

```
  reward r_t      one-step scalar signal      (given by environment)
  return G_t      sum of discounted rewards    (a random variable)
  value v(s)      E[return]                     (what we estimate)
```

The agent maximizes *expected return*. Reward is the per-step ingredient; value
is the learned expectation. Confusing them causes most early errors.

### "Is RL supervised learning with extra steps?"

No. In supervised learning the targets are fixed and given. In RL the "targets"
(returns or bootstrapped values) are produced by the agent's own current
estimates and policy, so the optimization target moves as you learn — a
non-stationarity that supervised theory does not model.

### "On-policy vs off-policy — why does it matter so much?"

On-policy methods learn about the policy they are currently executing.
Off-policy methods learn about a *different* target policy (e.g., the greedy one)
while behaving more exploratorily. Off-policy is more flexible and data-efficient
(you can reuse old data, a replay buffer) but mathematically more dangerous — it
is one leg of the deadly triad (ch 05).
