# maxim-fork

Use this skill before dispatching a pulse to an agent or before a long editorial
slice. The output is a single context file under the active wave.

## Usage

```text
/maxim-fork 02
```

## Procedure

1. Resolve the active wave from `context/waves/PHASES.md`.
2. Find `context/waves/{active}/pulses/NN+*.md`.
3. Read the pulse completely.
4. Extract `governing_roles` from frontmatter.
5. Resolve role notes:
   - Built-in MAXIM roles come from `.claude/skills/reference-review/SKILL.md`,
     `.claude/skills/atlas-review/SKILL.md`, and `.claude/skills/honor/SKILL.md`.
   - Card/archetype roles come from `cards/ROLES.md`.
   - If a role-specific file is absent, record the role name and use the pulse
     text as the contract.
6. Write `context/waves/{active}/forks/pulse-NN.md`.

## Fork File Format

```markdown
# Fork Context: Pulse NN - Title

> Generated by /maxim-fork. Read this file completely before acting.

## Pulse Plan

{verbatim pulse file}

## Governing Roles

{role notes or "no local role file found"}

## Execution Contract

- Work in the repository root.
- Use `rg` for search.
- Use `apply_patch` for manual edits.
- Do not revert unrelated user changes.
- Do not modify structural files unless the pulse explicitly names them.
- Check off pulse gates only after they are complete.
- Run the pulse validation commands before reporting done.
```

## Sync

If a fork is used as an execution receipt, copy completed checkbox state back to
the source pulse file after validation.
